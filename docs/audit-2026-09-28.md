# Portfolio audit — September 28, 2026

Site: [Vishnu Sai Bodapati](https://vsvwnl.github.io/).

This is an engineering and editorial review, not a study with recruiters, a hiring prediction, or an accessibility certification. Browser results below are from the production build in Chromium. Public-link responses were checked separately on this date.

## Recruiter verdict

The portfolio is distinctive and credible for an early-career interactive-software engineer. Its strongest positioning is Unity/C#, XR, spatial tools and gameplay systems. The direct introduction, Duke research affiliation, May 2027 graduation date and immediately available resume make the basics easy to establish. The restrained visual design supports that story without making visitors operate an elaborate interface to read it.

It can support general software and applied-AI applications, but the evidence is not equally strong in every category. Draft USA provides a public web codebase and recorded demo; more concrete implementation evidence would make that side of the profile more convincing. Do not broaden claims or invent metrics to compensate.

### What works

- **Identity and access:** “Vishnu Sai Bodapati,” the role, Duke context and the primary actions are visible in the tested desktop and 390px phone opening views. Resume and contact are repeated in the navigation/footer.
- **Ownership:** all four featured projects separate “My work” from team results. Case studies explain personal contribution, constraints and decisions rather than presenting awards as individual achievements.
- **Credibility:** CinemaScout has real footage; public Devpost and video evidence supports the hackathon projects. Lumi is explicitly research work, with a clearly labeled explanatory diagram and no invented clinical results.
- **Breadth with a thread:** XR, camera tools, Lua/Playdate, Unreal, computer vision and web/AI connect through interactive systems rather than a long badge collection.
- **Skill map:** every skill leads to a concrete project. It is supplemental navigation, not a prerequisite for finding evidence.

## Changes made in this pass

- Brief 650ms name/introduction entrances, 460ms one-time viewport reveals, and a 240ms skill-evidence transition. No looping decoration, opacity gating or added animation library.
- Content stays visible before JavaScript and if animation features are unavailable. Motion uses transforms without changing document layout.
- Reduced-motion preferences suppress CSS entrances and viewport animations. Changing that preference cancels active viewport motion; keyboard focus and direct section targets stay stationary.
- Starting the demo now transfers keyboard focus from the removed Play button to native video controls. The error fallback also has focus handling.
- Case-study section links now have 36px-high targets and 12px mobile text.
- Added repeatable motion tests, load-size budgets and an optional public-link diagnostic.

### Performance and limitations

The homepage's referenced JavaScript totals **76.3 KiB gzip** and its CSS **6.8 KiB gzip** in this build, below the new 100/10 KiB budgets. These figures exclude HTML, fonts and images. The approximately 4.65 MB demo is requested only after Play; it is not an initial video download. Project images have dimensions, and below-fold photos/posters use lazy loading.

Google Fonts remains an external dependency. Locally hosting a subset of the three font families is a reasonable future optimization, but no measured bottleneck is claimed here. The ignored 92.8 MB source MOV is not tracked/deployed by CI and is not referenced by the site; Vite can still copy it into a **local** build because it sits under `public/`. Do not mistake that local artifact for the production page payload.

No Lighthouse score, Core Web Vitals result, network-throttled benchmark, Safari/Firefox test, physical-device test or screen-reader certification is claimed. Reduced-motion behavior was tested in code and inspected in CSS; the browser tools did not expose OS-preference emulation. No JavaScript-disabled browser session was run: readable no-JS content was confirmed in the generated HTML. The video error path has source-level handling but was not forced in the browser.

The next meaningful improvement is better project evidence and faster access to ownership details—not additional decorative motion.
